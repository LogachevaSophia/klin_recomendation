# Упрощенные атрибуты для ноды условия

Для ноды условия (`condition`) теперь используются простые атрибуты вместо сложного парсинга.

## Атрибуты

Для ноды условия можно задать следующие атрибуты:

1. **`hint`** - Подсказка для пользователя, что именно нужно ввести
   - Пример: `"Введите систолическое давление"`

2. **`inputType`** - Тип данных, которые должен ввести пользователь
   - Возможные значения: `number`, `text`, `boolean`
   - По умолчанию: `text`

3. **`compareOperator`** - Знак сравнения
   - Возможные значения: `=`, `!=`, `<`, `>`
   - По умолчанию: `=`

4. **`compareValue`** - Значение, с которым нужно сравнить введенное значение
   - Пример: `"140"` для числа, `"true"` для boolean

5. **`inputField`** - Поле в данных пациента, куда сохраняется введенное значение
   - Может быть вложенным, например: `bloodPressure.systolic`
   - Если не указано, используется старая логика с ConditionEvaluator

## Пример использования

Для ноды условия с атрибутами:
- `hint`: "Введите систолическое давление"
- `inputType`: "number"
- `compareOperator`: ">"
- `compareValue`: "140"
- `inputField`: "bloodPressure.systolic"

Логика работы:
1. При подходе к ноде проверяется, есть ли значение в `patientData.bloodPressure.systolic`
2. Если значения нет, запрашивается ввод у пользователя с подсказкой "Введите систолическое давление"
3. После ввода значение сравнивается: `введенное_значение > 140`
4. Если условие истинно, переход по ветке `true`, иначе по ветке `false`

## Логика сравнения

Сравнение выполняется простыми if-блоками:
- `=` - равенство (используется `==` для гибкого сравнения)
- `!=` - неравенство
- `<` - меньше
- `>` - больше

Типы автоматически преобразуются:
- Для `number`: оба значения преобразуются в числа
- Для `boolean`: строки "true", "True", "Да", "да" преобразуются в `true`

## Обратная совместимость

Если атрибут `inputField` не указан, используется старая логика с `ConditionEvaluator` для оценки условий из атрибута `condition` или из `label` узла.
