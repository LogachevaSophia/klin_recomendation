# 📋 Документация проекта "Клинические Рекомендации"

## 🎯 Обзор проекта

**Клинические Рекомендации** - это веб-приложение для создания, редактирования и визуализации медицинских процессов в виде BPMN-диаграмм. Система позволяет медицинским специалистам создавать интерактивные процессы диагностики и лечения с поддержкой подпроцессов и циклических операций.

### ✨ Основные возможности

- 🔄 **Визуальное редактирование BPMN-процессов** с 6 типами функциональных нод
- 📑 **Многоуровневая навигация** с поддержкой подпроцессов и вкладок
- 🔗 **Интерактивные связи** между элементами процесса (вертикальная схема)
- 💾 **Управление рекомендациями** (создание, редактирование, удаление)
- 🎨 **Современный UI** с адаптивным дизайном и контекстными меню
- ⌨️ **Горячие клавиши** для повышения продуктивности
- 🖱️ **Drag & Drop** для быстрого добавления элементов
- 📋 **Контекстное меню** с действиями для элементов
- ❓ **Встроенная справка** с подсказками
- 🧪 **Mock-режим** для разработки и демонстрации

## 🎨 Типы функциональных нод

### 1. 🟢 StartNode (Стартовая нода)
```typescript
type: "start" | backend_type: 0
```
- **Назначение**: Точка начала процесса
- **Внешний вид**: Круглая зеленая нода с градиентом и иконкой ▶️
- **Подключения**: Только исходящие (`Bottom` - выход вниз)
- **Использование**: Каждый процесс должен иметь одну стартовую ноду
- **Цвета**: Зеленый градиент (#dcfce7 → #bbf7d0), граница #16a34a

### 2. 🔴 FinishNode (Финишная нода)
```typescript
type: "finish" | backend_type: 1
```
- **Назначение**: Точка завершения процесса
- **Внешний вид**: Круглая красная нода с градиентом и иконкой 🏁
- **Подключения**: Только входящие (`Top` - вход сверху)
- **Использование**: Процесс может иметь несколько точек завершения
- **Цвета**: Красный градиент (#fee2e2 → #fecaca), граница #dc2626

### 3. 🟡 ConditionNode (Нода условий)
```typescript
type: "condition" | backend_type: 2
```
- **Назначение**: Принятие решений на основе условий
- **Внешний вид**: Ромбовидная желтая нода (повернута на 45°) с иконкой ❓
- **Подключения**: 
  - `Top` (target): Вход сверху
  - `Bottom` (source): Основной выход (обычно "Да")
  - `Right` (source): Альтернативный выход (обычно "Нет")
- **Особенности**: Поддержка меток на рёбрах ("Да"/"Нет")
- **Цвета**: Желтый градиент (#fef3c7 → #fde047), граница #eab308

### 4. 🔵 ActionNode (Нода действий)
```typescript
type: "action" | backend_type: 3
```
- **Назначение**: Выполнение конкретных действий
- **Внешний вид**: Прямоугольная синяя нода с градиентом и иконкой ⚙️
- **Подключения**: 
  - `Top` (target): Вход сверху
  - `Bottom` (source): Выход снизу
- **Использование**: Основные рабочие элементы процесса
- **Цвета**: Синий градиент (#dbeafe → #93c5fd), граница #2563eb

### 5. 🟦 SubprocessNode (Нода подпроцессов)
```typescript
type: "subprocess" | backend_type: 4
```
- **Назначение**: Ссылка на вложенный подпроцесс
- **Внешний вид**: Прямоугольная голубая нода с иконкой 📋
- **Подключения**: 
  - `Top` (target): Вход сверху
  - `Bottom` (source): Выход снизу
- **Особенности**: 
  - При клике открывает новую вкладку
  - Содержит `subprocess_id` для загрузки данных
  - Показывает подсказку "Нажмите для открытия"

### 6. 🟣 LoopNode (Нода циклов)
```typescript
type: "loop" | backend_type: 5
```
- **Назначение**: Циклическое выполнение операций
- **Внешний вид**: Прямоугольная фиолетовая нода с иконкой ⟲
- **Подключения**: 4 точки подключения
  - `Top` (target): Основной вход в цикл
  - `Bottom` (source): Основной выход из цикла
  - `Right` (source): Начало тела цикла
  - `Left` (target): Возврат в цикл
- **Дополнительные поля**:
  - `loopCondition`: Условие продолжения цикла
  - `maxIterations`: Максимальное количество итераций

#### 🔄 **Паттерны для циклов с множественными действиями**

**Подход 1: Последовательная цепочка действий**
```
Loop → Action1 → Action2 → Action3 → Condition → Loop/Exit
```
- ✅ **Преимущества**: Простота, наглядность
- ⚠️ **Недостатки**: Может загромождать диаграмму при большом количестве действий

**Подход 2: Подпроцесс для тела цикла (Рекомендуется)**
```
Loop → Subprocess → Condition → Loop/Exit
```
- ✅ **Преимущества**: Чистота диаграммы, переиспользование, модульность
- ✅ **Лучше для**: Сложных циклов с 3+ действиями

**Пример использования:**
- **Простой цикл**: Измерение температуры каждый час
- **Сложный цикл**: Комплексный мониторинг (измерения + анализ + запись + уведомления)

## 🔗 Схема соединений

### 📐 Вертикальная архитектура

Все ноды используют **вертикальную схему соединений** для лучшей читаемости процессов:

```
    ┌─────────────┐
    │  StartNode  │ ▶️
    │   (Green)   │
    └──────┬──────┘
           │ Bottom (source)
           ▼
    ┌──────────────┐
    │ ActionNode   │ ⚙️  
    │   (Blue)     │
    └──────┬───────┘
           │ Bottom (source)
           ▼
    ┌──────────────┐
    │ ConditionNode│ ❓
    │  (Yellow)    │
    └─┬─────────┬──┘
      │ Bottom  │ Right
      ▼         ▼
   (Да)      (Нет)
```

### 🎯 Преимущества вертикальной схемы

- ✅ **Естественное чтение**: Сверху вниз, как блок-схема
- ✅ **Компактность**: Меньше горизонтального пространства
- ✅ **Стандартность**: Соответствует BPMN практикам
- ✅ **Масштабируемость**: Легко добавлять новые этапы

### 🔄 Специальные случаи

#### ConditionNode (Ветвления)
- **Основной поток**: `Top → Bottom` ("Да")
- **Альтернативный поток**: `Top → Right` ("Нет")

#### LoopNode (Циклы)
- **Основной поток**: `Top → Bottom` (вход → выход)
- **Тело цикла**: `Right → Left` (начало → возврат)

## 🔧 API и структуры данных

### Backend структуры данных

#### BackendNode
```typescript
interface BackendNode {
  id: number;                    // Уникальный ID ноды
  type: number;                  // Тип ноды (0-5)
  data: {
    label: string;               // Отображаемый текст
  };
  json_data: {
    x: number;                   // Координата X (масштабируется *200)
    y: number;                   // Координата Y (масштабируется *100)
  };
  subprocess_id: string | null;  // ID подпроцесса (для type=4)
}
```

#### BackendEdge
```typescript
interface BackendEdge {
  id: string;                    // Уникальный ID связи
  source: number;                // ID исходной ноды
  target: number;                // ID целевой ноды
}
```

#### BackendData
```typescript
interface BackendData {
  process_id: string;            // ID процесса
  name: string;                  // Название процесса
  nodes: BackendNode[];          // Массив нод
  edges: BackendEdge[];          // Массив связей
}
```

### Frontend структуры данных

#### BpmnNode
```typescript
interface BpmnNode {
  id: string;                    // Строковый ID
  type: "start" | "finish" | "subprocess" | "condition" | "action" | "loop";
  position: Position;            // Координаты для ReactFlow
  data: {
    label: string;
    subprocess_id?: string;      // Для подпроцессов
    attributes?: Attribute[];    // Дополнительные атрибуты
    loopCondition?: string;      // Для циклов
    maxIterations?: number;      // Для циклов
  };
}
```

## 💾 Система управления состоянием

### BpmnStore (MobX)
Центральное хранилище для управления BPMN процессами:

```typescript
class BpmnStore {
  processes: Map<string, ProcessData>  // Все загруженные процессы
  activeProcessId: string              // ID активного процесса
  
  // Getters
  get initialNodes(): BpmnNode[]       // Ноды активного процесса
  get initialEdges(): Edge[]           // Связи активного процесса
  get availableProcesses()             // Список доступных процессов
  
  // Methods
  setActiveProcess(processId: string)  // Переключение процесса
  updateMainProcess(id: string)        // Загрузка главного процесса
  addNewNode(node: BpmnNode)          // Добавление новой ноды
  updateNodes(nodes: BpmnNode[])      // Обновление нод
  updateEdges(edges: Edge[])          // Обновление связей
}
```

## 📋 Лучшие практики для циклов

### 🎯 Когда использовать какой подход

#### Простые циклы (1-2 действия)
```
Loop → Action → Condition → Loop/Exit
```
**Используйте для:**
- Простых повторяющихся измерений
- Базовых проверок состояния
- Циклов с одним ключевым действием

#### Сложные циклы (3+ действий)
```
Loop → Subprocess → Condition → Loop/Exit
```
**Используйте для:**
- Комплексных процедур мониторинга
- Многоэтапной обработки данных
- Процессов с условными ветвлениями внутри цикла

### 🔄 Примеры реализации

#### Пример 1: Простой цикл измерений
```typescript
// Структура: Start → Loop → Measure → Check → Loop/Finish
// Подходит для: базового мониторинга с одним действием
```

#### Пример 2: Сложный цикл с подпроцессом
```typescript
// Главный: Start → Loop → Subprocess → Condition → Loop/Finish
// Подпроцесс: SubStart → Action1 → Action2 → Action3 → SubFinish
// Подходит для: комплексных многоэтапных процедур
```

### ⚙️ Настройка LoopNode

```typescript
// Базовая конфигурация
{
  type: "loop",
  data: {
    label: "Цикл мониторинга",
    loopCondition: "count < maxIterations",
    maxIterations: 10
  }
}
```

**💡 Рекомендации:**
- Для 1-2 действий: используйте прямые связи
- Для 3+ действий: выносите в подпроцесс
- Всегда задавайте максимальное количество итераций
- Используйте понятные условия выхода
